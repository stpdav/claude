# Google Ads MCP - Claude Code Setup Guide (Ubuntu WSL)

Sets up Google's official read-only Google Ads MCP server (`github.com/googleads/google-ads-mcp`) in Claude Code, scoped to the user (all projects, never committed to git).

**What you get:** two tools - `list_accessible_customers` and `search` (GAQL). Read-only: no bid changes, no campaign creation, no writes of any kind.

**Prerequisites:** Ubuntu WSL, Python 3.10+, git, gcloud CLI, a Google Ads MCC account with access to the target client account.

---

## 1. Google Cloud project

1. Go to [console.cloud.google.com](https://console.cloud.google.com) → project picker → **New project** → name it (e.g. `pharmacyonline-ads-mcp`) → Create.
2. Note the **project ID** - needed later as `GOOGLE_PROJECT_ID`.
3. **APIs & Services → Library** → search "Google Ads API" → **Enable**.

## 2. OAuth consent screen

**APIs & Services → OAuth consent screen** (labelled "Google Auth Platform" in newer console versions):

1. User type: **External** (or Internal if your Ads login is on a Workspace org).
2. Fill in app name, support email, developer email → Save.
3. Skip the scopes step - the server requests `https://www.googleapis.com/auth/adwords` at runtime.
4. If External: add your own Google account under **Test users**.

> **Testing-mode caveat:** while the consent screen is in Testing, refresh tokens expire after 7 days. Symptom: `401 UNAUTHENTICATED` roughly a week after setup. Fix: re-run step 4 below, or publish the app to make tokens permanent (the "unverified app" warning only appears on your own consent screen).

## 3. OAuth client → client_secret.json

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**.
2. Application type: **Desktop app** → name it → Create → **Download JSON**.
3. Move it into WSL (Linux filesystem, not `/mnt/c`):

```bash
mkdir -p ~/.config/gads
mv /mnt/c/Users/<you>/Downloads/client_secret_*.json ~/.config/gads/client_secret.json
chmod 600 ~/.config/gads/client_secret.json
```

> This file is only the OAuth **client definition** - it is not usable as credentials by itself. Step 4 turns it into actual credentials.

## 4. Generate Application Default Credentials (ADC)

This is the step most guides miss. The server authenticates via ADC, which needs a credentials file containing a refresh token - generated by gcloud:

```bash
gcloud auth application-default login \
  --client-id-file=$HOME/.config/gads/client_secret.json \
  --scopes=https://www.googleapis.com/auth/adwords,https://www.googleapis.com/auth/cloud-platform
```

- A browser consent flow opens (WSL2 forwards to your Windows browser; if not, paste the printed URL manually - the localhost callback works because WSL2 shares localhost with Windows).
- Approve with the Google account that has MCC access.
- Writes credentials to `~/.config/gcloud/application_default_credentials.json` - **this** is the file `GOOGLE_APPLICATION_CREDENTIALS` points at.

## 5. Developer token

1. Sign in to the **MCC** (not the client account).
2. Tools & Settings (wrench) → Setup → **API Center** → copy the 22-character developer token.
3. Access level:
   - **Test account only** - fresh tokens start here; won't work against production accounts.
   - **Basic** - 15,000 operations/day; fine for reporting. Apply via the form in API Center (usually approved within a day).
   - **Standard** - unlimited; not needed for GAQL reporting.

## 6. Install the server (venv - not pipx)

> **Why not pipx:** the apt-packaged pipx on Ubuntu 24.04 (v1.4.3) has a bug - it crashes with `json.decoder.JSONDecodeError: Expecting value: line 1 column 1` when pip prints a notice to stdout. A plain venv avoids it entirely and also gives instant startup (no per-launch git clone, no MCP handshake timeouts).

```bash
sudo apt install -y python3.12-venv git   # if not already present
python3 -m venv ~/.local/venvs/google-ads-mcp
~/.local/venvs/google-ads-mcp/bin/pip install git+https://github.com/googleads/google-ads-mcp.git
```

Smoke-test - it should sit silently waiting on stdin (Ctrl+C to exit); any error prints immediately:

```bash
GOOGLE_APPLICATION_CREDENTIALS=$HOME/.config/gcloud/application_default_credentials.json \
GOOGLE_PROJECT_ID=<your-project-id> \
GOOGLE_ADS_DEVELOPER_TOKEN=<your-token> \
~/.local/venvs/google-ads-mcp/bin/google-ads-mcp
```

To update later:

```bash
~/.local/venvs/google-ads-mcp/bin/pip install --upgrade git+https://github.com/googleads/google-ads-mcp.git
```

## 7. Register with Claude Code (user scope)

User scope = stored in `~/.claude.json`, available in every project, never committed:

```bash
claude mcp add google-ads --scope user \
  --env GOOGLE_APPLICATION_CREDENTIALS=$HOME/.config/gcloud/application_default_credentials.json \
  --env GOOGLE_PROJECT_ID=<your-project-id> \
  --env GOOGLE_ADS_DEVELOPER_TOKEN=<your-token> \
  -- ~/.local/venvs/google-ads-mcp/bin/google-ads-mcp
```

Verify:

```bash
claude mcp list
```

The command shown must be the venv binary path (`/home/<you>/.local/venvs/...`), **not** `pipx run ...`.

> **Removing an old entry:** `claude mcp remove` defaults to `local` scope. If a stale entry was added with `--scope user`, remove it with `claude mcp remove google-ads --scope user` - otherwise the remove silently does nothing and the old command keeps running.

## 8. Test

In a Claude Code session:

1. `/mcp` - confirm `google-ads` shows as connected.
2. Ask: **"List my accessible Google Ads accounts"** - should return the MCC and client account(s).
3. Ask a real query, e.g.:
   - "Show me search terms from the last 30 days that cost more than £50 with zero conversions, sorted by cost"
   - "For each enabled campaign, show today's spend against its daily budget"
   - "Campaign performance for the last 7 days - spend, conversions, CTR, cost per conversion"

Tip: state the customer ID once per session ("use account 1234567890 for everything") - 10 digits, hyphens stripped.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `CONNECTION_CLOSED` on connect | Server process dies before handshake | Run the smoke-test command from step 6 manually to see the real error |
| pipx `JSONDecodeError: Expecting value` | Ubuntu 24.04 apt pipx bug | Use the venv route (step 6) |
| `claude mcp remove` doesn't remove | Scope mismatch - remove defaults to `local` | Add `--scope user` |
| `401 UNAUTHENTICATED` after ~a week | Consent screen in Testing mode; refresh token expired | Re-run step 4, or publish the app |
| `PERMISSION_DENIED` | Developer token still at test-account level | Apply for Basic access in API Center |
| `INVALID_ARGUMENT` on customer_id | Hyphens in the ID | Strip hyphens - 10 digits only |
| `USER_PERMISSION_DENIED` on client account | `login_customer_id` (MCC ID) not being sent | Flag it - needs the MCC ID set explicitly |
| Server missing from `/mcp` | Stale/failed registration | `claude mcp list` to inspect; remove + re-add |

## File and secret hygiene

- `~/.config/gads/client_secret.json` - OAuth client definition (chmod 600)
- `~/.config/gcloud/application_default_credentials.json` - actual credentials (refresh token; treat as a secret)
- Developer token - secret; lives only in `~/.claude.json` via the env block, never in a repo
- User scope keeps everything out of `.mcp.json`, so nothing for gitleaks to catch and nothing the team inherits
